# SDK test vectors

Cases that the Rust and TypeScript SDKs must both pass, so they accept and
reject the same inputs. [docs/architecture/sdk.md](../../docs/architecture/sdk.md)
describes the behavior they pin down.

Do not edit these files by hand. They are generated by
`crates/common/tests/sdk_vectors.rs` from the fixed keys in `keys/` and the
shared protocol types, and signed with auth's own signer. Run `just sdk-vectors`
after changing the generator; `just test` fails while the committed files are stale.

`keys/` holds two throwaway RSA keys, `key-2025` (before a rotation) and
`key-2026` (after it). They exist only to make the signatures reproducible.

## Case format

Each file is one case:

```json
{
  "description": "what the case checks",
  "now": 1767225600,
  "input": {},
  "expected": { "ok": {} }
}
```

- `now` is the Unix time the SDK's injected clock returns. It is present only for
  time-dependent cases.
- `expected` is either `{ "ok": value }` or
  `{ "error": { "code": "...", "reason": "..." } }`. `code` is an error category and
  `reason` the check that failed, from `piquel_common::protocol::sdk`. `reason` is
  omitted for categories without one.

## Categories

| Directory | `input` | `ok` |
| --- | --- | --- |
| `discovery/` | `issuer` configured, `document` returned by the well-known endpoint | the parsed metadata |
| `jwks/` | `jwks`, a key set | `kids`: the usable key IDs, in set order |
| `tokens/` | `issuer`, `jwks`, `kind` (`access`, `id` or `logout`), `audience` (the resource, or the client for ID and logout tokens), `token`; ID tokens add `nonce` and `max_age` (`null` when not sent) | the token's claims |
| `challenges/` | `challenge` (format cases) or `header` (parse cases) | `status` and `header`, or `challenge` |
| `callbacks/` | `issuer`, `authorization_response_iss_parameter_supported`, the expected `state`, and the callback's query `parameters` | `code` |

Challenge format cases go both ways: `challenge` must format to exactly `header`,
and `header` must parse back to `challenge`. Parse cases only parse, since their
headers are not in canonical form; `challenge` is `null` when the header holds no
valid Bearer challenge.
